# Take a Pic: the Hybrid ISP website

A small, plain website that shows how a phone turns sensor data into a photo, using our three ISPs
(Classic, Learned, Hybrid).

Live: https://hemansshu-raaj--take-a-pic.us-east.modal.run (deploy with `make deploy`, see `deploy_modal.py`).

There's no build step. The frontend is plain HTML, CSS and JavaScript. The backend is one small
FastAPI app that calls the ISP code in `../isp`.

## Run it

```bash
make web          # from the repo root  ->  http://localhost:8000
make web-test     # backend tests (pipelines + API), ~15 s
make web-e2e      # whole-site browser test, needs `make web` running and playwright-cli installed
                  #   (npm install -g @playwright/cli); ~1 min, prints one "ok" line per check
```

The API docs are at http://localhost:8000/api/docs.

## Common changes

| I want to... | Edit |
|---|---|
| Change a stage's title or explanation | `site/content/stages.json` |
| Change the example files' names | `EXAMPLES` in `api/service.py` |
| Add or reorder a stage | the `trace_*` function in `api/trace.py`, then the same id in `stages.json` (`order`). `make web-test` checks both agree |
| Change the small facts under a stage (chips) | `CHIPS` in `site/js/method.js` |
| Change the vortex (speed, swirl, glow) | the shader and `target`/`rate` in `site/js/vortex.js` |
| Change the menu zoom or the pop-out key (height, bounce) | `zoom()` / `POP_HEIGHT`, `POP_DEPTH`, `updatePop()` in `site/js/phone3d.js` |
| Add or change an Advanced setting (phone's 4th menu item) | `SETTINGS` in `site/js/screen-ui.js`, `settings` in `site/js/api.js` (URL keys), `clean_options()` in `api/service.py` |
| Change the phone screen's words | `TEXT` in `site/js/screen-ui.js` |
| Change the title's wording or font | `.venv/bin/python web/tools/make_lettering.py "New words"` |
| Change the phone's shape | `blender/build_phone.py`, then re-run it (command at the top of the file) |
| Change the phone's comic look (line roughness, dots, colours) | `STYLE` / `PALETTE` in `site/js/phone3d.js`; preview at `/dev/phone.html` |
| Make processing faster or slower | `MAX_PIXELS` / `COMPARE_PIXELS` in `api/service.py` |

## Page flow

Front page → drop a RAW photo (or an example) on the phone → it slides open and offers
Classic / Learned / Hybrid → the phone turns round and the view flies into its camera lens →
`classic.html` (etc.) opens with the flare vortex, the photo un-twists out of it → scroll one stage
per screen → the finished photo → all three ISPs compared on the bundled examples.

## How a request flows

1. On the front page a RAW file is dropped on the phone. It goes to `POST /api/upload`, which checks
   it can be read and returns an `upload_id`. Ordinary photos (JPG, HEIC, ...) are refused with a
   friendly message. The example cards send an example id instead of a file.
2. The method page calls `POST /api/process` with `{method, upload_id | example}`. The reply has the
   final image and one entry per stage: `{id, image, zoom, info}`. Images are data URLs. `zoom` is
   a 40×40 sensor-pixel close-up of the same spot in every stage.
3. At the bottom of each method page, `GET /api/compare/{example}` runs all three methods on a
   bundled example. For the SIDD examples it adds PSNR, SSIM and ΔE against the ground truth.
